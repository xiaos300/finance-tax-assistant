# 技术选型与架构决策

版本：1.1｜日期：2026-11-01｜关联：[总体架构](02_系统总体架构设计.md)。数据库按用户明确要求修订为PostgreSQL。

## 1. 推荐技术栈

下表为确定的实施方案。主版本/系列是兼容目标，不声称均是最新补丁；精确依赖锁由下一阶段安装、构建和集成探针通过后生成。本阶段没有安装或测试这些框架。

| 层 | 推荐方案 | 有意义的替代及放弃原因 | 成本、风险与适用条件 |
| --- | --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Vue Router、Pinia；原生CSS与fetch | React同样可行；当前无既有代码，Vue单文件组件便于小团队实现聊天/弹层 | 学习成本中；避免再引入大型组件套件、SSR和多套请求库 |
| 后端 | Python 3.13、FastAPI、Pydantic 2、Uvicorn单worker | Spring Boot需要第二语言栈；Flask需自行补契约与校验 | API与模型链同一Python栈；async路由不能直接执行长同步事务 |
| 持久化 | PostgreSQL 18维护系列、psycopg 3、SQLAlchemy 2.0维护系列、Alembic | MySQL可支撑事务，但用户已指定PostgreSQL；不维护第二数据库实现 | 增加一个db服务及连接池/角色/备份配置；统一开发、测试、演示数据库 |
| 模型 | 自编ModelGateway+HTTPX AsyncClient；原生函数工具调用能力契约 | Agent框架增加状态与隐藏行为；MCP无现成外部服务需求 | 实现一类实际供应商协议；账号、模型ID和端点待Q-004，不承诺任意“兼容”服务即用 |
| 知识 | PostgreSQL元数据查询+完整相关正文+受控JSONB策略 | 向量RAG可能返回不适用版本且多一存储；正则从正文直接执行难验证 | 五版本无需语义库；规则维护需同步正文与策略，成本低至中 |
| 数据准备 | Python Decimal、datetime、openpyxl一次转换，规范化JSON seed | Pandas/Polars对此样本无收益；运行期解析Excel会混淆现状 | 仅准备/测试需要openpyxl，正文人工核对后规范化；绝不改原文件 |
| 金额 | PostgreSQL BIGINT分，Python int与Decimal做边界转换；整数SUM | NUMERIC(18,2)也精确，但本版保留amount_cents/threshold_cents契约，避免无必要改单位；禁止float | PostgreSQL SUM(bigint)返回精确numeric，仓储验证整数后转Python int；API仍输出元字符串 |
| 缓存/队列 | 无Redis、无消息队列、无业务BackgroundTasks | Celery/Redis仅在独立长任务与吞吐证据成立后评估 | 普通请求内有限工具循环；重启不自动续写，接受明确恢复边界 |
| 部署 | 多阶段Docker构建，FastAPI托管Vue静态包；Compose app+db两个服务 | 无Docker可原生Python+静态包连接已安装PostgreSQL；不另加nginx/worker | db健康后执行显式迁移/seed并启动app；命名卷保留数据，不提供HA |
| 验证 | Pytest、HTTPX API测试、Vitest、Playwright少量核心E2E | 不上压力测试平台与完整测试管理系统 | 重点业务边界/真实模型合同/故障点，不为每个getter写测试 |
| 证据 | PostgreSQL evidence_events（JSONB）+Python结构化运维日志 | ELK/OTel收集平台增加服务，样本不足以支撑收益 | 关联轮次与企业；实发payload脱敏记录，禁止模型密钥、数据库凭证与隐藏推理 |

## 3. ADR登记

下列决策均为本阶段已采用设计，后续触发条件成立时才重评。实现验证仍未完成。

### ADR-001：模块化单体与同源部署

- 背景/问题：BR-001/008要求可复验主链路；资源有限而S7/S8要求网页。
- 候选：脚本、单体、微服务；前后端分别部署或同源打包。
- 决策：Vue独立开发，FastAPI模块化单体、演示同源静态包。
- 理由/成本：统一模型工具链，免跨服务追踪和跨域凭证；增加前端构建但满足已确认交互。
- 权衡/风险：单进程故障影响全链路，部署不能分别扩容；保持模块协议以便维护。
- 重评条件：明确独立发布需求、多个后端实例或长任务隔离要求。

### ADR-002：用户指定PostgreSQL与整数分

- 背景/问题：DR-001—DR-005与FR-007要求精确金额、复合定位、保存可核验。
- 候选：PostgreSQL、MySQL；本轮用户明确指定PostgreSQL，不再保留其他数据库作为MVP运行或测试替代。
- 决策：PostgreSQL 18维护系列+psycopg 3同步驱动+SQLAlchemy 2.0+Alembic；金额BIGINT分、JSONB结构化资料、TIMESTAMPTZ时间；连接池与短事务。
- 理由/成本：尊重用户技术约束，提供原生关系约束、并发事务和标准备份；保留整数分与既有API/策略单位，减少连带变更。成本为新增db服务、角色初始化与连接配置。
- 权衡/风险：数据库启动/凭证/网络/连接池成为运行条件，必须隔离迁移角色与应用角色、限制锁等待；数据库支持多客户端不代表单进程Harness已可水平扩容。
- 重评条件：用户或正式部署环境要求调整主版本/托管形态；未来多实例需另行设计执行租约、重启恢复所有权及模型并发协调，不自动重放旧操作。

### ADR-003：普通Python Harness与原生工具调用

- 背景/问题：FR-002必须真实模型决策，但FR-006禁止模型自行越权。
- 候选：关键词场景脚本、自编循环、Agent框架。
- 决策：ModelGateway返回类型化tool_calls/final，Dispatcher只允许注册工具；模型不接触数据库连接与系统命令。
- 理由/成本：以较少依赖展示真实输入、决策与工具结果；需自行实现轮数、超时、参数和授权校验。
- 权衡/风险：模型错误理解无法被JSON校验完全消除；意图证据与对抗测试见08。供应商待Q-004，不假定API通用。
- 重评条件：实际出现无法用有限工具循环处理的工作流，且框架能改善可测性而非隐藏状态。

### ADR-004：规则元数据与有限结构化策略

- 背景/问题：FR-012/013要求正文可管理且不能依赖模型任意文字作合规判断。
- 候选：每企业if分支、模型自由判断、规则元数据+策略枚举、向量检索。
- 决策：按企业/业务时间/启用状态/主题查规则；用途策略all或amount_gte（threshold_cents）；正文与策略同一修订提交。
- 理由/成本：五版本可精确查找，更新无需改对话脚本；CLI维护者明确策略，程序不猜正文含义。
- 权衡/风险：正文与策略可能不一致；CLI显示差异，要求维护者核对，不能宣称自动理解任意新法规。复杂全新策略需代码扩展。
- 重评条件：新增已确认的策略类型或大量非结构化知识检索；先加验证器，再评估RAG。

### ADR-005：操作账本、CAS与独立回读

- 背景/问题：FR-006/007要求超时不重复写，已保存不等于已核验。
- 候选：只信UPDATE返回、写前比较、事务账本+回读。
- 决策：轮内稳定操作ID和唯一payload指纹，事务原子保存票据+账本，row_version比较更新；提交后全新Session重查。
- 理由/成本：能解释提交后掉线和回读失败；write_operations表及状态机有必要。
- 权衡/风险：回读失败仍是待核验；查询到同值不证明本次真的修改过，需区分already_current与verified。
- 重评条件：跨存储事务或远端业务写入出现，再评估outbox等机制；当前不引入。

### ADR-006：同步轮次与按需查询状态

- 背景/问题：模型有延迟，但没有逐token展示或大批处理需求。
- 候选：同步HTTP、SSE、WebSocket、后台队列。
- 决策：请求内执行，持久化轮次，GET状态支持断连恢复；取消仅阻止尚未提交的后续步骤。
- 理由/成本：省连接协议和Worker，用户仍可看到处理中与最终事实；默认一次一轮。
- 权衡/风险：长连接受浏览器/代理超时影响，断连不能判断失败。刷新只查状态，不能自动重放POST。
- 重评条件：实测长时间运行或确认流式体验需求；引入SSE也不能改变写入核验语义。

### ADR-007：受控演示身份与本机知识管理

- 背景/问题：Q-002未规定登录技术；U001/U002权限必须可信。
- 候选：客户端user_id、完整账号系统、预置随机凭证。
- 决策：运维生成高熵演示token与用户绑定，服务端验证；网页凭证输入框，规则CLI依赖本机文件访问权。
- 理由/成本：不建设注册/管理员后台，避免信任模型和浏览器身份。凭证不打包，README说明生成方式。
- 权衡/风险：token泄露可被复用；回环演示边界、恒时比较、退出清理、公开部署前重设鉴权。
- 重评条件：真实多用户、互联网部署或官方指定鉴别方案。

### ADR-008：记忆失效与历史证据保留

- 背景/问题：FR-010与Q-007要求删除后不使用，但未承诺历史彻底擦除。
- 候选：仅删行、全部历史重写、版本失效+按需重建。
- 决策：记忆更正/删除增加用户memory_revision；新轮Context重建、不回放旧摘要/旧工具记忆；历史Evidence受控保留、不参与检索输入。
- 理由/成本：避免删除后摘要“复活”；无需再建摘要数据库。
- 权衡/风险：历史消息可能重复用户旧偏好，必须过滤旧偏好/记忆来源；日志仍含历史模拟证据，政策需告知。
- 重评条件：要求彻底擦除历史/备份或出现自动摘要能力；同步补生命周期方案。

### ADR-009：保持Must完整并延后增强

- 背景/问题：一周规模容易只完成问答而遗漏管理、引用与范围语义。
- 候选：缩减Must或先闭环再补齐。
- 决策：FR-001—FR-016全部进入MVP；FR-017/018、跨企业金额Should延后。
- 理由/成本：保留用户与官方已确定范围；以迭代顺序控制开发风险。
- 权衡/风险：网页与故障语义仍有实现成本，实际投入未知；不能用文档覆盖声称软件通过。
- 重评条件：新通知或用户明确调整范围，先改需求基线再改架构。
