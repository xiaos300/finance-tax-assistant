# 非功能架构设计

版本：1.2｜日期：2026-11-01｜依据：NFR-001—NFR-009与[未决问题](../requirements/05_待确认问题与风险.md)，运行数据库统一PostgreSQL。本阶段是保障方案，未执行软件性能、安全、模型或部署验收。并发revision/取消结算的实施细节见[12](12_开发实施契约补充.md)，逐项fixture和步骤见[测试规范](../development/04_测试与验收规范.md)。

性能风险主要是模型网络、工具循环过多与过量历史，不是88条业务记录的数据库扫描。日期与企业组合索引足够；不加缓存，避免旧规则/旧权限/旧用途被复用。只读批量明细分页，工具优先返回汇总和必要票据，不一次装载所有企业历史。

建议工程默认值：模型单次read timeout 45秒、connect timeout 5秒、轮总预算120秒、最多6次模型调用、最多12次工具调用、消息正文上限8000字符、引用最多20项、用途/备注每字段4000字符、HTTP体128KiB。这些均非官方限制，是防失控初值，须在模型与设备探针后调整并写启动说明。超限明确错误，不截断后执行；单轮120秒并不保证5分钟演示能完成，必须用实际排练调整调用次数和模型。

## 2. 身份、资源与数据保护

演示token由维护命令生成随机至少256位熵，分别绑定U001/U002，环境只提供验证配置，不进仓库或打包。Bearer仅保存在浏览器内存，刷新重新输入；后端恒时比较，禁止接受X-User-ID或聊天“我是U001”改身份。默认仅监听回环映射，HTTP适用本机演示；若经网络访问需HTTPS并重新评估正式身份方案，当前不宣称公网可用。

所有操作先检查会话归属，再校验实际企业。查询尽量把授权company谓词放SQL；修改必须同时验证write、企业复合键与字段白名单。memory/evidence也检查用户所有权和企业可读范围；U002在C001可管理自己的记忆，不因此可改发票；他人同企业记忆仍不可见。隐藏控件只改善体验，不能替代后端限制。

参数严格schema、枚举与长度校验，SQL参数绑定，搜索字符转义。无业务文件上传端点，原始资料只由受控CLI准备；输入/备份文件路径与数据库目标分别校验，重置要求 APP_ENV=test 和 finance_tax_test 精确允许名单及认证后目标/实例/角色核验，并比对解析后的连接目标不得等于演示库。应用账号不持有SUPERUSER/CREATEDB/DDL权限，权限/规则/银行表只读，发票采用列级UPDATE授权；维护账号只在显式迁移/seed/规则维护/恢复命令使用。数据库不默认暴露宿主端口，远程托管连接使用TLS校验；DATABASE_URL、迁移URL与数据库密码和模型密钥同样敏感。普通业务工具不开放文件系统、shell、任意URL请求或SQL工具。

## 3. 当前轮写授权与模型边界

模型承担语义理解，程序不能用关键词脚本替代；同时，模型输出一个`authorized=true`并不成立授权。采用以下可检查约束：

1. 初始意图分析只接收当前用户文字、经过验证的引用标识和最小必要指代线索，不接收票面备注等非可信内容作为指令。模型给出动作/字段/内容证据的当前文本位置或明确清空证据。
2. Guard验证证据位置落在当前user消息原文内；内容值必须来自当前用户明确内容，不能来自票面项目/历史任务。引用/历史可帮助定位对象，不提供本轮修改意愿。动作表述仍由模型判断，不能仅“字符串存在”就允许写。
3. 目标必须唯一且经程序校验；文字与引用企业/日期冲突、引号内讨论修改但没有执行意图、多票内容对应不清等走needs_input。模型必须在结构化proposal中区分询问/引用/否定与执行；无法证实时不写。
4. Guard生成当前轮内部intent_handle，限定user/session/turn/company/invoice/changes。Dispatcher执行时再次检查写权限、字段、操作账本、行版本、取消标识。同轮同票不能通过重复工具调用产生不同修改。
5. 返回事实以实际回读为准；前端事实卡片由程序生成。模型最终输出采用结构化段落与fact引用，金额、规则名称版本、成功状态由程序渲染；自由解释不得宣称工具不支持的事实。违规格式可纠正一次，仍无效只显示真实程序结果并标答复生成失败。

**剩余风险必须保留**：文本证据位置和类型校验不能数学证明自然语言授权；模型可能误解否定、转述或复杂指代。不能宣称已完全阻断所有提示注入。下一阶段必须以真实模型测试“别改/如果改/他说要改/忽略权限”等反例；错误写入是阻断交付的问题。对语义证据不充分的个案追问，不增加每次写入机械确认。模型失败时程序事实卡片只反映已发生操作，不冒充模型已完成任务。

规则正文、发票/流水备注、检索内容标明untrusted_data，无法更改系统规则、身份、工具schema；维护的policy_json是有限枚举，不eval、不执行正文代码。政策未知或冲突时停止合规判断。API密钥只在ModelGateway请求头使用，程序配置不给模型。

## 4. 上下文预算与删除记忆后的输入

每个ModelGateway声明实际上下文上限、工具schema开销、输出保留量和token计数方案，启动验证`MAX_INPUT_TOKENS+MAX_OUTPUT_TOKENS+工具/安全余量≤供应商上限`。供应商未定前不填假定最大token数。优先使用该模型兼容tokenizer；若只能估算，须保守留余并以供应商探针验证，不能宣称严格token保证。

每次模型调用的输入按顺序组成：可信身份/权限与系统约束→本轮原话及已验证引用→默认与实际对象/月/更正→当前任务必要线索→相关规则正文及revision→所需当前工具事实→必要最近历史。必须保留元素过大时分步读/分页或显式说明限制，不能截掉身份或最新更正。工具schema和工具结果同样计入预算。

范围定位阶段未确定企业时只给授权企业与候选任务短标签，不注入各企业完整任务/偏好/规则。确定实际乙后取乙材料，保留甲默认状态作为状态事实，不带甲专属正文。其他企业历史仅在理解明确指代时给必要标识，不能把其旧事实当现状。

Context不全量回放原messages或evidence_events；没有长期自动摘要。每轮读users.memory_revision，任何task/preference变更后重建选择结果。消息带memory_refs_json；删除/更正后旧记忆工具结果、旧偏好声明与对应管理答复块全部排除新输入，仅保留必要且不携带旧内容的状态标记。并发删除时在每次后续模型调用前复核revision，变化则重建；已经发送中的外部请求无法撤回，应中止使用该轮旧结果并提示重新开始，不继续据旧记忆写。删除不能撤销此前已经合法保存的票据或已发送的历史模型输入。

## 5. 超时、重试与一致性

| 故障 | 策略 | 不允许的行为 |
| --- | --- | --- |
| 模型超时/限流/5xx | 尚无写时可对瞬态失败至多重试1次并记录，尊重Retry-After且不得超轮预算；费用不保证不重复计费 | 静态场景答案冒充成功、无限循环 |
| 模型输出非法参数 | schema拒绝，最多一次纠正；未通过不执行 | 自动删掉越界字段后擅自保存 |
| 数据库不可达/连接池耗尽/锁超时 | 有界连接、pool_timeout、lock_timeout和statement_timeout；失败回滚，再按阶段判断是否需核验 | 将失败当空记录、在中止事务继续查询或盲目重放写 |
| 单票CAS冲突 | STALE_DATA并重新读取，必要时向用户澄清 | 覆盖新值、拿搜索row_version当当前版本 |
| 提交响应不确定 | 查原操作账本与当前值，保持verify_pending直到有证据 | 无新事实即再次UPDATE |
| 写已提交但回读失败 | 保存待核验，任务保留，后续只读核验 | 回滚口头承诺或报已核实 |
| 回读成功但任务/证据后续失败 | 已保存事实保留，显示进度/证据更新失败 | 重写发票“补救”日志 |
| 进程重启 | 遗留轮interrupted，当前数据/记忆保留，账本可查 | 自动续跑旧写授权 |
| 客户端断连/刷新 | 用原turn_id查状态；取消需显式请求 | 换ID自动重发、把Abort当回滚 |

单票票据与committed账本原子写，核验与任务刷新分开。多票明确逐项状态。未实现FR-017的自动续办不影响上述FR-007基础保护必须交付。

实现时还须落实12 §5/7：事务内按固定锁顺序复核memory_revision，历史消息/轮结果也检查当前企业权限；模型调用前的检查不能代替提交前检查。截止/协程取消不能把仍在执行的线程提交当作已回滚，须有界等待数据库结算。测试增加TC053—TC060验证这些交错，而不是仅顺序调用接口。

## 6. 证据、运维日志与保留

Evidence在每次真实调用前记录最终发送payload，模型返回后记录合法响应字段与tool_calls；不记录SDK对象repr、HTTP请求头、环境dump或隐藏思维链。模型输入原文/工具说明中的本地配置秘密也须先识别：SecretRedactor对已知凭证精确值与敏感键递归脱敏后再发模型/落证据，凭证验证材料不可进入输入。用户误贴配置秘密时拒绝发送该秘密并提示；脱敏内容与真实实发内容一致，不能日志显示脱敏而实际发送密钥。请求头中的鉴权由Gateway单独处理。

运维日志字段：timestamp/level/component/request_id/session_id/turn_id/company_ids/stage/duration_ms/error_code；默认不记完整正文。开发可写`var/logs/app.jsonl`，建议10MiB×3轮转为可调默认；容器主要stdout。数据库evidence_events保留结构化实发材料，便于查看。没有集中式监控依赖，不宣称hash能防恶意管理员改库。

默认不自动过期历史证据，记忆删除仅停止未来使用；这一政策已在架构选择但Q-007仍待负责人确认。清理历史必须在备份与交付策略明确后由本机维护执行，不能静默删关键运行证据。提交只选必要模拟轮次和干净当前库，不包含本地真实凭证、无关个人输入或整套用户历史。

日志不可用：写前无法记录授权/准备则拒绝写；写后独立Evidence失败仍依赖同事务write_operations标记实际提交，回复显示证据缺口。读取失败与无事件不同，不能伪造成功记录。

## 8. 扩展点与技术债

ModelGateway只实现一个实测供应商适配，切换模型需重验工具参数、预算、语义与费用；Repository统一使用PostgreSQL，不维护第二方言。未来采用托管PostgreSQL或多实例应用时，需重新验证连接池、TLS、迁移锁、运行轮所有权/恢复和模型并发协调，不能仅增加Uvicorn worker。新增用途策略修改枚举/验证器/测试，不增加企业if分支；新增完全不同业务能力才新增模块。

当前接受单进程、无自动续跑、无逐token输出、无全局通用偏好、无自动历史擦除、规则语义需维护者核对。明确触发需求时再做Worker/SSE/全局偏好范围/有效区间，不预建空基础设施。开发AI应按[交接](11_架构评审与开发交接.md)完成核心闭环再考虑增强。
