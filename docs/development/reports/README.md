# 阶段报告与证据目录

本目录已有的source_manifest是复审前19份来源的hash，review_validation是设计文档校验结果；它们不是软件运行验收。现已有 [D0实现报告](2026-11-03_D0_baseline.md)及同名证据目录，失败复验记录在D0_attempt1/2/3；D1—D7未实施。

后续每阶段使用`<日期>_<阶段>_<短标识>.md`，需要大量证据时配同名目录。报告最少包含以下实际内容，不能仅填空模板：

1. 用户授权范围、阶段、需求/契约版本，Git commit或source_tree_hash。
2. 完成行为与实际修改文件，API/数据库迁移/依赖影响。
3. 仅记录该阶段特有的实际执行、测试和验收命令、工作目录、退出码及必要环境版本；未执行命令不要混入结果。通用安装与启动步骤链接根目录 [README 开发者统一启动说明](../../../README.md)，不在报告复制维护。验收实际启动命令可作为明确标注阶段/用途的历史证据保留，不作为当前操作指南。
4. TC/子项和AC对应、fixture/seed hash、模型none/stub/real及profile标识，passed/failed/blocked/not_run/not_in_scope。
5. 证据路径及turn/invocation/call/operation关联，提交/回读事实与敏感信息扫描；程序事实与模型措辞分开。
6. local/external/overall门逐项结论，仍缺条件、风险、下一可独立推进任务与progress更新链接。

从 D0 起，启动说明必须随工程持续维护。任何阶段改变启动方式，须在同次变更更新 README、替换失效步骤、核对脚本与配置示例，并在报告注明启动说明的变更及验证范围；未改变则注明已核对。历史报告和原始日志保留当期事实，读者执行当前启动时统一转到 README。

阶段交付还必须执行根目录 [Markdown 文档引用、锚点与可追溯性规范](../../../AGENTS.md#markdown-文档引用锚点与可追溯性规范)，将新增/修改 Markdown 的路径、锚点检查和关键结论人工追溯核对结果纳入验收记录。

summary.json 字段和通过规则见[测试规范的运行记录与通过条件](../04_测试与验收规范.md#4-运行记录与通过条件)。报告禁止真实token/模型密钥/数据库密码或完整敏感URL。真实模型缺失写blocked，本地替身通过也不能冒充live；设计修订只标设计完成，不能关闭软件测试。
