## harness schema 是否需要同步更名

**不需要。建议保留 harness。** 数据库是连接目标，schema 是该数据库内部命名空间；`finance_tax_dev.harness.invoices` 的意思是连接 finance_tax_dev 后访问 harness.invoices。PostgreSQL 不因此提供跨数据库三段名查询。两个库内均可拥有名为 harness 的独立 schema，数据库名不要求与 schema 同名，依据[官方 schemas](https://www.postgresql.org/docs/18/ddl-schemas.html)。

| 选项 | 影响与评价 |
| --- | --- |
| A：保留 harness（建议） | 最小改动：新库名/角色名/测试保护正式同步；保留 D0 search_path、既定 Alembic schema、SQL 限定名和备份 schema。不会把任何对象建进原来的 harness 数据库 |
| B：统一改为 finance_tax | 可以，但不是用户四名称的必然后果。需另批后修改 D0 engine、ORM metadata/FK/命名、Alembic env/version_table_schema、权限 SQL、ready/seed inspect、备份恢复与相关断言，再复验。若有既有对象还需独立迁移方案，不能只 ALTER SCHEMA 然后继续旧代码 |

以下可执行 SQL **全部采用选项 A**。批准 schema B 时须先重写并复核方案，不混用两种 schema。当前没有部署/迁移任何 schema。

## finance_tax_test 的安全保护替代方案

[原安全规则](../../architecture/05_数据库与数据架构设计.md#10-初始化迁移与备份)要求 APP_ENV=test、harness_test_ 前缀、与演示目标不同；finance_tax_test 不符合旧前缀。不能删掉保护、改成包含 test、允许 finance_tax_ 全前缀或支持任意 *_test。推荐批准后以**固定允许名单 finance_tax_test**替换旧命名前缀这一条件，其余检查继续保留并落实；首轮仍只允许串行一个库。

1. 应用正常连接仅允许明确配置的 finance_tax_dev；测试执行只允许 finance_tax_test。所有项目真实连接入口预先拒绝 tax_db，以及其他未批准目标；不能靠改当前工作目录、环境文件或 APP_ENV 获得新目标。
2. 测试必须 APP_ENV=test；TEST_DATABASE_URL 与 TEST_MIGRATION_DATABASE_URL 同时显式提供，驱动必须 postgresql+psycopg，db 字段**精确等于** finance_tax_test。缺任一项报错，不回落 DATABASE_URL/MIGRATION_DATABASE_URL，不从系统 PGDATABASE/PGSERVICE 补目标。
3. 对主连接、维护连接、测试连接规范化解析，核对批准实例（首轮候选 127.0.0.1:5432）、端口、库名及用途；测试 app/维护必须指向同一测试库，开发 app/维护同理，开发与测试三元组不同。localhost/127.0.0.1/::1 的可判定别名做保守同目标比较；未知/多主机、service/hostaddr 等可覆盖目标的 DSN query 参数先拒绝，不在缺少证明时视为安全新实例。
4. 首个连接仅做身份/目标核对：current_database()、session_user、current_user、inet_server_addr()/port() 与用途一致后，才允许迁移、清理、seed 或 fixture；业务/测试角色不能是 postgres、超级用户或拥有 CREATEDB/CREATEROLE。app 期望 finance_tax_app，维护期望 finance_tax_migrator，角色无越权继承或 SET ROLE 路径；目标不一致立即关闭，不能“先清再验”。
5. 重置必须再次复核精确目标、环境和状态，使用维护连接及固定 schema/表清单；该允许名单不是删除/重置授权。本轮以及未获授权的后续操作都不因名字包含 test 就可 DROP 库/卷或清数据。测试要用真实 PG、真实 COMMIT/新 Session，数据隔离与权限反例不变。
6. 当前不自动允许 finance_tax_test_*、旧 harness_test_* 或 pytest worker 后缀。将来并行必须明确批准 worker 目标集合、预建库流程和保护验收；不能悄悄扩大匹配范围。未知旧名无连接 unit fixture 可以保留，不能作为集成/重置入口。

这些是**待实现保护设计**，不是宣称当前 D0 已具备。其落地点包括测试 settings、engine/Session 创建入口、conftest、reset/seed/迁移封装、备份恢复及 CLI，需在正式 D1 授权后执行。[来源扫描](2026-11-04_D1_naming_review/reference-audit.json)与现有 config.py/engine.py 表明 D0 没有真正的测试重置保护实现。

## tax_db 的保护边界

所有下面的修改语句只作用于新建的 finance_tax_dev、finance_tax_test、这两库的 harness/public schema 及新建的两个角色。**不对 tax_db 执行 ALTER、REVOKE、GRANT、DROP、恢复、seed 或业务查询；不改 pg_hba.conf、监听或服务，不终止既有连接，不以 tax_db 为模板。** 同名新目标/角色存在即停止，不自动重用、改名、接管或删掉重建。

必须区分“不修改 tax_db”与“数据库服务器绝对拒绝新角色连接 tax_db”：PostgreSQL 角色属于整个集群，PUBLIC 权限授予所有角色；若 tax_db 对 PUBLIC 有 CONNECT 或其他权限，新角色可能继承这类公共访问。单独 REVOKE 给某个角色不是拒绝规则，不能覆盖 PUBLIC 的授予。依据[官方权限模型](https://www.postgresql.org/docs/18/ddl-priv.html)与[REVOKE](https://www.postgresql.org/docs/18/sql-revoke.html)。本方案不改 tax_db 的 ACL，所以**不承诺数据库层的绝对不可访问**；项目程序须拒绝以其为目标。若还要求新角色从服务器层也绝不能访问 tax_db，应先获准只读审计现有 ACL/认证策略，或选独立实例；不得为达此目的擅改 tax_db 或全局认证。

两库共享 finance_tax_migrator 也意味着维护身份有能力操作开发与测试库，因此测试精确目标保护不可省略；不能声称仅改库名就实现物理隔离。app 的发票字段白名单、逐请求企业校验和只读银行维持[原角色契约](../../architecture/12_开发实施契约补充.md#63-运行角色与bootstrap)。

## 可执行 SQL 方案

**以下所有 SQL 本轮均未执行，未做数据库解析/运行验收。** SQL 是供确认后在 PostgreSQL 18/pgAdmin 分阶段执行的方案，不是已接入工程的脚本。上下文不符或对象存在即报错，失败停止并保留结果；不提供任何 DROP/重置补救命令。不同阶段不得合成一个“全选执行”脚本。

### A 只读前核对

未来用 pgAdmin 以预计的 postgres 连接系统维护库 postgres，先打开 Query Tool（不要选择 tax_db），只执行本段。必须确认 server_version 为 18、current_database=postgres、session_user/current_user=postgres 且具有管理员能力；若账号不是预期值，先核实身份，不能改密码或提升权限。本段只读系统目录，不进入 tax_db。

```sql
BEGIN READ ONLY;
SELECT current_database(), session_user, current_user;
SHOW server_version;
SELECT rolname, rolsuper, rolcreatedb, rolcreaterole, rolcanlogin
FROM pg_catalog.pg_roles
WHERE rolname IN ('postgres','finance_tax_app','finance_tax_migrator');
SELECT datname, pg_catalog.pg_get_userbyid(datdba) AS owner,
       pg_catalog.pg_encoding_to_char(encoding) AS encoding
FROM pg_catalog.pg_database
WHERE datname IN ('finance_tax_dev','finance_tax_test','tax_db');
COMMIT;
```

预期仅新两库/两角色不存在；tax_db 行仅用于确认保护对象的目录登记，不读取内容。若新目标已存在，停止后续 CREATE，另审查其来源/归属，不使用 IF NOT EXISTS 掩盖冲突。

### B 一次性创建两角色

确认没有同名角色、明确批准执行后，仍在 postgres 维护库，以 postgres 运行；整个 DO 是一个原子语句。没有口令明文，创建后由用户在 pgAdmin 的角色 Properties → Definition 设置各自独立口令，未设置前不假定能进行密码登录。安全属性与无成员关系须在 UI 核对。

```sql
DO $bootstrap$
BEGIN
  IF current_database() <> 'postgres'
     OR session_user <> 'postgres' OR current_user <> 'postgres'
     OR NOT EXISTS (SELECT 1 FROM pg_catalog.pg_roles
                    WHERE rolname = current_user AND rolsuper) THEN
    RAISE EXCEPTION 'STOP: expected postgres administrator on postgres database';
  END IF;
  IF current_setting('server_version_num')::integer NOT BETWEEN 180000 AND 189999 THEN
    RAISE EXCEPTION 'STOP: PostgreSQL 18 required';
  END IF;
  IF EXISTS (SELECT 1 FROM pg_catalog.pg_roles
             WHERE rolname IN ('finance_tax_app','finance_tax_migrator')) THEN
    RAISE EXCEPTION 'STOP: target role exists; review ownership before any change';
  END IF;
  CREATE ROLE finance_tax_migrator LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE
    NOREPLICATION NOBYPASSRLS;
  CREATE ROLE finance_tax_app LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE
    NOREPLICATION NOBYPASSRLS;
END;
$bootstrap$;
```

两角色初始无父角色，不执行角色间 GRANT。pgAdmin 是口令输入途径，不把含 PASSWORD 的 SQL 复制回聊天、报告或共享脚本；角色对话框位置见[官方 pgAdmin role dialog](https://www.pgadmin.org/docs/pgadmin4/latest/role_dialog.html)。

### C 分别创建两个新数据库

在 postgres 维护库启用 Auto-commit，无显式 BEGIN、无待处理事务；**每次只选中一条 CREATE DATABASE 执行**，成功后检查结果再执行下一条。角色 B 与只读查重必须先成功。CREATE DATABASE 不能放在事务块/DO 中；template0 避免从用户业务库或自定义 template1 复制，依据[官方 CREATE DATABASE](https://www.postgresql.org/docs/18/sql-createdatabase.html)。也可使用 pgAdmin Databases → Create → Database，Owner=finance_tax_migrator、Encoding=UTF8、Template=template0，名称逐字核对，[官方数据库对话框](https://www.pgadmin.org/docs/pgadmin4/latest/database_dialog.html)。两种方式二选一，不重复建库。

```sql
CREATE DATABASE finance_tax_dev
  OWNER finance_tax_migrator ENCODING 'UTF8' TEMPLATE template0;
```

```sql
CREATE DATABASE finance_tax_test
```

### D 两个新库各自初始化 schema 和连接权限

以 postgres 分别在新库 finance_tax_dev、finance_tax_test 的 Query Tool 中各执行一次**完整事务**。只用于本方案刚创建且经核对的新库；schema 已存在就中止，不当作修复脚本。schema harness 推荐保留。此阶段不建业务表、不迁移/seed。

```sql
BEGIN;
DO $prepare$
DECLARE
  db_name text := current_database();
BEGIN
  IF db_name NOT IN ('finance_tax_dev','finance_tax_test')
     OR session_user <> 'postgres' OR current_user <> 'postgres'
     OR NOT EXISTS (SELECT 1 FROM pg_catalog.pg_roles
                    WHERE rolname = current_user AND rolsuper) THEN
    RAISE EXCEPTION 'STOP: wrong database or bootstrap identity';
  END IF;
  IF NOT EXISTS (
    SELECT 1 FROM pg_catalog.pg_database d
    WHERE d.datname = db_name
      AND pg_catalog.pg_get_userbyid(d.datdba) = 'finance_tax_migrator'
      AND pg_catalog.pg_encoding_to_char(d.encoding) = 'UTF8'
  ) THEN
    RAISE EXCEPTION 'STOP: owner or encoding differs';
  END IF;
  IF EXISTS (SELECT 1 FROM pg_catalog.pg_namespace WHERE nspname = 'harness') THEN
    RAISE EXCEPTION 'STOP: harness schema already exists';
  END IF;
  IF (SELECT count(*) FROM pg_catalog.pg_roles
      WHERE rolname IN ('finance_tax_app','finance_tax_migrator')
        AND rolcanlogin AND NOT rolsuper AND NOT rolcreatedb AND NOT rolcreaterole
        AND NOT rolreplication AND NOT rolbypassrls) <> 2
     OR EXISTS (SELECT 1 FROM pg_catalog.pg_auth_members m
                JOIN pg_catalog.pg_roles r ON r.oid = m.member
                WHERE r.rolname IN ('finance_tax_app','finance_tax_migrator')) THEN
    RAISE EXCEPTION 'STOP: unexpected role attributes or memberships';
  END IF;
  CREATE SCHEMA harness AUTHORIZATION finance_tax_migrator;
  EXECUTE format('REVOKE ALL PRIVILEGES ON DATABASE %I FROM PUBLIC', db_name);
  EXECUTE format('REVOKE ALL PRIVILEGES ON DATABASE %I FROM finance_tax_app', db_name);
  EXECUTE format('GRANT CONNECT ON DATABASE %I TO finance_tax_app', db_name);
  EXECUTE format('ALTER ROLE finance_tax_app IN DATABASE %I SET search_path TO harness, pg_catalog', db_name);
  EXECUTE format('ALTER ROLE finance_tax_migrator IN DATABASE %I SET search_path TO harness, pg_catalog', db_name);
END;
$prepare$;
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
REVOKE ALL PRIVILEGES ON SCHEMA public FROM finance_tax_app;
REVOKE ALL PRIVILEGES ON SCHEMA harness FROM PUBLIC;
REVOKE ALL PRIVILEGES ON SCHEMA harness FROM finance_tax_app;
GRANT USAGE ON SCHEMA harness TO finance_tax_app;
ALTER DEFAULT PRIVILEGES FOR ROLE finance_tax_migrator IN SCHEMA harness
  REVOKE ALL PRIVILEGES ON TABLES FROM finance_tax_app;
ALTER DEFAULT PRIVILEGES FOR ROLE finance_tax_migrator IN SCHEMA harness
  REVOKE ALL PRIVILEGES ON SEQUENCES FROM finance_tax_app;
COMMIT;
```

这些 REVOKE/ALTER ROLE IN DATABASE 仅作用于当前两个新库，不是对 tax_db 或整个集群的全局配置修改。默认权限影响未来由该角色创建的对象，不会修复已有表授权；不使用默认全表 UPDATE，依据[官方默认权限说明](https://www.postgresql.org/docs/18/sql-alterdefaultprivileges.html)。迁移以 migrator 登录创建对象，不依赖 postgres 会话的默认权限。

### E 正式 D1 迁移和 seed 后才授运行表权限

当前业务表不存在，**现在不得执行本段**。正式 D1 授权并实现测试目标保护后，先在 finance_tax_test 用 finance_tax_migrator 登录执行首迁移/seed，再运行下列事务；测试通过后对明确批准的 finance_tax_dev 执行同样维护链。两库都需首迁移实际对象与所有者核对。运行角色本身不能负责迁移或 grant-runtime，维护过程无模型依赖。

下段只授本方案已列 16 张表及证据序列；如有缺表、额外表/视图或所有者不符，先中止审查，不自动扩大白名单。先撤销旧表级及列级授权，再按列重授，避免仅撤表级留下历史列权限。REVOKE 列权限语法依据[官方 REVOKE](https://www.postgresql.org/docs/18/sql-revoke.html)。

```sql
BEGIN;
DO $grant_guard$
DECLARE
  expected text[] := ARRAY[
    'companies','users','user_company_permissions','invoices','bank_transactions',
    'sessions','turns','messages','rules','rule_companies','tasks','preferences',
    'write_operations','evidence_events','seed_meta','alembic_version'
  ];
  entry record;
BEGIN
  IF current_database() NOT IN ('finance_tax_dev','finance_tax_test')
     OR session_user <> 'finance_tax_migrator'
     OR current_user <> 'finance_tax_migrator' THEN
    RAISE EXCEPTION 'STOP: expected explicit project maintenance connection';
  END IF;
  IF NOT EXISTS (SELECT 1 FROM pg_catalog.pg_database d
                 WHERE d.datname = current_database()
                   AND d.datdba = current_user::regrole
                   AND pg_catalog.pg_encoding_to_char(d.encoding) = 'UTF8')
     OR NOT pg_catalog.has_database_privilege('finance_tax_app', current_database(), 'CONNECT')
     OR pg_catalog.has_database_privilege('finance_tax_app', current_database(), 'CREATE')
     OR pg_catalog.has_database_privilege('finance_tax_app', current_database(), 'TEMP')
     OR NOT pg_catalog.has_schema_privilege('finance_tax_app', 'harness', 'USAGE')
     OR pg_catalog.has_schema_privilege('finance_tax_app', 'harness', 'CREATE')
     OR pg_catalog.has_schema_privilege('finance_tax_app', 'public', 'CREATE') THEN
    RAISE EXCEPTION 'STOP: database owner or schema/database privileges differ';
  END IF;
  IF NOT EXISTS (SELECT 1 FROM pg_catalog.pg_namespace
                 WHERE nspname = 'harness' AND nspowner = current_user::regrole)
     OR (SELECT count(*) FROM pg_catalog.pg_class c
         JOIN pg_catalog.pg_namespace n ON n.oid = c.relnamespace
         WHERE n.nspname = 'harness' AND c.relkind IN ('r','p')
           AND c.relname = ANY(expected) AND c.relowner = current_user::regrole) <> 16
     OR EXISTS (SELECT 1 FROM pg_catalog.pg_class c
                JOIN pg_catalog.pg_namespace n ON n.oid = c.relnamespace
                WHERE n.nspname = 'harness' AND c.relkind IN ('r','p','v','m','f')
                  AND NOT (c.relname = ANY(expected))) THEN
    RAISE EXCEPTION 'STOP: schema/table ownership or table set differs';
  END IF;
  IF (SELECT count(*) FROM pg_catalog.pg_roles
      WHERE rolname IN ('finance_tax_app','finance_tax_migrator')
        AND rolcanlogin AND NOT rolsuper AND NOT rolcreatedb AND NOT rolcreaterole
        AND NOT rolreplication AND NOT rolbypassrls) <> 2
     OR EXISTS (SELECT 1 FROM pg_catalog.pg_auth_members m
                JOIN pg_catalog.pg_roles r ON r.oid = m.member
                WHERE r.rolname IN ('finance_tax_app','finance_tax_migrator')) THEN
    RAISE EXCEPTION 'STOP: unexpected role attributes or memberships';
  END IF;
  FOR entry IN
    SELECT c.relname, a.attname FROM pg_catalog.pg_class c
    JOIN pg_catalog.pg_namespace n ON n.oid = c.relnamespace
    JOIN pg_catalog.pg_attribute a ON a.attrelid = c.oid
    WHERE n.nspname = 'harness' AND c.relkind IN ('r','p')
      AND a.attnum > 0 AND NOT a.attisdropped
  LOOP
    EXECUTE format('REVOKE ALL PRIVILEGES (%I) ON TABLE harness.%I FROM finance_tax_app',
                   entry.attname, entry.relname);
    EXECUTE format('REVOKE ALL PRIVILEGES (%I) ON TABLE harness.%I FROM PUBLIC',
                   entry.attname, entry.relname);
  END LOOP;
END;
$grant_guard$;
REVOKE ALL PRIVILEGES ON ALL TABLES IN SCHEMA harness FROM finance_tax_app, PUBLIC;
REVOKE ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA harness FROM finance_tax_app, PUBLIC;
GRANT SELECT ON harness.companies, harness.users, harness.user_company_permissions,
  harness.invoices, harness.bank_transactions, harness.sessions, harness.turns,
  harness.messages, harness.rules, harness.rule_companies, harness.tasks,
  harness.preferences, harness.write_operations, harness.evidence_events,
  harness.seed_meta, harness.alembic_version TO finance_tax_app;
GRANT UPDATE (memory_revision) ON harness.users TO finance_tax_app;
GRANT UPDATE (purpose, note, row_version, updated_at) ON harness.invoices TO finance_tax_app;
GRANT INSERT, UPDATE ON harness.sessions, harness.turns, harness.messages,
  harness.write_operations TO finance_tax_app;
GRANT INSERT, UPDATE, DELETE ON harness.tasks, harness.preferences TO finance_tax_app;
GRANT INSERT ON harness.evidence_events TO finance_tax_app;
DO $sequence_grant$
DECLARE
  seq_name text;
BEGIN
  SELECT c.relname INTO seq_name FROM pg_catalog.pg_class c
  JOIN pg_catalog.pg_namespace n ON n.oid = c.relnamespace
  WHERE c.oid = pg_catalog.pg_get_serial_sequence('harness.evidence_events','event_id')::regclass
    AND c.relkind = 'S' AND n.nspname = 'harness'
    AND c.relowner = current_user::regrole;
  IF seq_name IS NULL THEN
    RAISE EXCEPTION 'STOP: evidence identity sequence missing or owner differs';
  END IF;
  EXECUTE format('GRANT USAGE, SELECT ON SEQUENCE harness.%I TO finance_tax_app', seq_name);
END;
$sequence_grant$;
COMMIT;
```

运行失败时事务应回滚后停止，不提交半套权限、不启动 app 冒充 ready。正式 grant-runtime 仍须核验数据库 CONNECT/schema USAGE/no CREATE 及所有者/继承/默认授权的实际有效权限，不只核对上面的 GRANT 文本。首迁移或服务 DML 若与方案不符，先记录并修订，经授权后再实施，不通过 GRANT ALL 解决失败。

```sql
BEGIN READ ONLY;
DO $verify_context$
BEGIN

$verify_context$;
SELECT current_database(), session_user, current_user;
SHOW search_path;
```
