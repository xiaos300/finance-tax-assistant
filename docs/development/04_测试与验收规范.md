# 测试与验收规范

版本：1.0｜日期：2026-11-01｜唯一详细用例定义：[test-cases.json](test-cases.json)。本轮只创建定义，所有用例初始not_run。

## 1. 定义、类型与模型模式

每例包含id、ac_refs、前置条件、initial_data、steps、expected、test_type、model、evidence、stage、priority、status。TC001—TC050分别对应AC-001—AC-050，TC051—TC061补实施风险；TC040/041/050可选，剩余58项必测定义覆盖47项Must AC。测试编号不替代原AC，也不是主办方测试或评分细则。

model=none只测确定性程序/DB/API/CLI；stub使用APP_ENV=test的FakeModel，必须记录为替身；real使用通过probe的实际模型；real_and_stub需分别记录本地分支和live分支，不能以一项pass合并掩盖另一项blocked。未配置模型时允许本地门完成，真实分支一律blocked，不能标not_applicable。TC049的纯文本连续闭环及TC031/036必须有real记录。

测试可用Pytest标记`unit/postgresql/api/fault_injection/model_contract/live`，前端Vitest、Playwright标case_id。一个AC有多个边界时可拆参数化子项，报告列出每一子项；阶段提前测子集只记子集通过，整TC不能提前关闭。

## 3. 必须具备的故障与并发控制点

命名故障点：before_prepare、before_commit、after_commit_before_response、readback_error、readback_mismatch、evidence_before_write、evidence_after_commit、task_update_error、model_timeout、model_invalid_json。用显式屏障暂停线程/协程以复现TC054/056/058，不能靠随机sleep碰运气。

“有效UPDATE次数”按原票row_version增量、受控SQL执行计数与操作账本交叉核对；Evidence UPDATE不计为业务修改。重复模型调用次数、HTTP尝试次数和票据有效修改次数分别统计。断连不是回滚；commit不确定先查账本/现值，验证不能盲重试。

## 4. 运行记录与通过条件

每个run生成`reports/<run_id>/`，run_id含日期/阶段/随机短标识，不含用户秘密。至少有summary.json与简短说明；存在真实调用/操作再存必要证据。summary字段：run_id、stage、commit或source_tree_hash、requirements_version、contract_version、runtime_versions、fixture_id、seed_hash、model_mode、model_profile_id（无密钥）、command、exit_code、case_results、evidence_paths。case_results逐子项使用passed/failed/blocked/not_run/not_in_scope，并说明原因。

真实证据包括请求/轮/invocation/call/operation标识、实际wire正文、规则revision、记忆revision、读写前后差异、独立回读与最终答复。拒绝例证明零有效写；无权限例另外证明无受限内容泄露。失败发生于Evidence后写时用原子write_operations补最小事实并标证据缺口，不手写模型记录补齐。

所有报告/日志/截图/包不得含真实token、模型密钥、数据库URL密码、无关个人资料；秘密扫描使用专门测试标记，不在报告附真实配置。测试secret必须在发送前被屏蔽或拒绝，不能只把日志脱敏而仍发送原密钥。

阶段通过按任务卡门；完整MVP通过须：TC001—TC039、TC042—TC049、TC051—TC061全部必要子项通过；所有real/real_and_stub必须完成真实分支；47项Must AC可逐一定位证据；≤5分钟演示、干净启动/备份恢复和DEL清单齐全。正式通知未取得时，只可称“候选交付已验证”，不能宣称满足未知提交条件。

## 5. 命令与实施边界

以下是后续工程应提供的命令，**本次未安装依赖/运行应用或业务测试**；目录、锁文件和对应测试创建前不能照抄宣称通过。

```text
# backend目录，先按锁安装dev依赖；首次锁生成在D0单独报告
uv sync --frozen --group dev --group prepare
uv run --frozen --no-sync pytest tests/unit
uv run --frozen --no-sync pytest tests/integration tests/api
uv run --frozen --no-sync pytest tests/model_contract -m live

# frontend目录
npm ci
npm run typecheck
npm run test -- --run
npm run build

# 项目根，D4后提供root e2e脚本/配置和锁
npm run test:e2e
```

live命令额外要求ALLOW_REAL_MODEL_TESTS=true、MODEL_MODE=live、已验证profile和预算；否则应skip并在验收汇总记blocked，不能把pytest绿色视为真实模型通过。PG测试连接由TEST_DATABASE_URL/TEST_MIGRATION_DATABASE_URL提供，夹具不得回落使用DATABASE_URL。无PG连接时PG测试门blocked；不能静默改用另一个数据库。

根e2e工程由D4创建root package.json/package-lock.json与Playwright配置，或将任务明确迁至frontend并同步所有命令；本计划固定前者，避免命令没有实际所属工程。报告字段和阶段完成规则详见[报告规范](reports/README.md)。
